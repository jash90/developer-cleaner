Get back the gigabytes node_modules and builds ate

One scan with Developer Cleaner turns up your node_modules folders, build folders such as Cargo's target, Pods or .next, and merged Git worktrees; a separate one covers the shared developer caches behind them. It tells you how much space a delete actually frees, not just how big the files look on paper.

Your disk fills up on its own

Every JavaScript project carries its own node_modules, every build leaves an output folder behind, every branch you open with git worktree is another full checkout, and package managers keep their caches outside your projects entirely. Give it a few months and that adds up to tens of gigabytes nobody is watching.

node_modules

Left behind in projects you haven't opened in months. npm install brings them back when you return.

Build folders

Cargo's target, Pods, .next, .nx, .turbo, .cxx, coverage, .expo. The next build or install recreates them.

Merged worktrees

The branch landed in main long ago, yet its working directory and dependencies are still on disk.

Tool caches

npm, pnpm, bun, yarn, uv, Gradle, old puppeteer browsers and Node versions under nvm, all living outside your projects.

Why “folder size” often lies
Case What naive sizing reports What you actually get back
node_modules under pnpm or bun the full size of every file close to nothing: the files are hardlinks into a shared store, and the data survives the delete
Sparse files (VM disk images) the nominal size, sometimes hundreds of GB only the blocks that were really written
Cloud-evicted files (iCloud Drive) the nominal size nothing, because the bytes aren't on this machine

What it does

An overview first, then a page for each category, and one review before anything is deleted.

Overview

The overview first, details when you want them

After a scan you see straight away how much space you can get back and where it comes from, not a long list of folders to scroll through.

  • The total to reclaim and a disk bar: each category's share, the free space now and after removing everything found.
  • Four cards with each category's total and largest items. Review all › opens the full list.
  • Suggestions, safest first. One click selects only low-risk items from a single category, such as abandoned stores or clean, unlocked worktrees. The rest open a filtered list to review.
  • Cards fill in as each scan returns. Progress is measured against the last scan of the same folder, and Stop ends a scan without showing partial results.
node_modules

Fast scans, honest sizes

Point it at a folder such as ~/Projects and Rust walks it in parallel with Rayon.

  • Each row shows what a delete actually frees. When the nominal size differs, hovering over the size shows it, with why the two differ.
  • The package manager is detected from the lock file: npm, yarn, pnpm or bun.
  • Technologies from package.json appear as badges: next, react, expo, @nestjs, vue, astro and more.
  • Sort by name, size or package manager; select rows one by one or all at once.
Build folders

Build folders, only where their tool left them

The same scan finds build output and tool caches inside your projects: Cargo's target, CocoaPods' Pods, .next, .nx, .turbo, Android's .cxx, coverage and .expo.

  • A folder is offered only when the tool that made it left its marks beside and inside it: a target needs a Cargo.toml beside it and Cargo's CACHEDIR.TAG inside, Pods a Podfile and Manifest.lock, coverage an actual coverage report.
  • Never when Git tracks anything inside it, so committed Pods and lookalike folders are left alone. The same check runs again right before the delete.
  • Each tool has its own group and checkbox, with a “What you lose” note in the group's header: a Rust target means a full rebuild and takes the release binaries kept there with it.
  • Nothing selects the folders of several tools at once: not selecting every node_modules folder, and not the suggestions, which only open a filtered list for build folders.
Git worktrees

Merged worktrees, squash merges included

The app refreshes remote-tracking refs first, then compares every worktree against all of the repository's base branches: origin/HEAD, main, master, development and develop.

  • Recognises squash merges, GitHub's default, without leaving objects behind in the repository.
  • Worktrees with uncommitted changes can be selected, but are removed only once you explicitly accept losing those changes. Worktrees locked by Git can't be selected.
  • Entries whose directory is already gone are cleared with git worktree prune.
  • Filters: clean, with uncommitted changes, locked, and those left with only a Git registration.
  • Branches are kept. Only the working directory goes.
Developer caches

Caches outside your projects, no folder needed

These caches live at fixed locations, so the app scans them as soon as it opens, before you pick a folder.

  • npm (_cacache, _npx), bun, yarn Berry and Classic, old Gradle versions, superseded puppeteer builds, old Node versions under nvm.
  • Abandoned pnpm stores left behind when pnpm moved its default location, told apart from the store it uses today.
  • The active pnpm store and the uv cache are handed to their own prune, so whatever is still in use stays.
  • Homebrew logs are emptied in place, because deleting a file a service holds open would not free the space.
  • Select safe picks only the safe entries. Anything that needs review is a deliberate click.
Safety

One review before anything is removed

Everything you select on any screen, node_modules, build folders, worktrees and caches alike, ends up in one Review and Remove… panel. It shows each category with its count and the space it frees, and you can still untick any item there.

  • For build folders the panel repeats what you lose for each selected tool, and for caches their notes.
  • Worktrees with uncommitted changes are named in a box pinned above the buttons. Remove and discard changes stays disabled until you tick that those changes will be permanently lost, and Keep Everything is the default button.
  • When the list of such worktrees changes, for example after you untick one of them, consent has to be given again.
  • That consent covers only the worktrees listed. A worktree that was clean at scan time and has changes by the time you click Remove is still refused.
  • Removal is refused if a worktree gained a commit after the scan.
  • OS and watcher junk (.DS_Store, watchman cookies) is reported separately: it isn't work, even though it makes git worktree remove refuse.
  • A worktree locked by Git is never force-removed.
  • A failure in one category doesn't stop the others. The result says, per category, how many items were removed, how many failed and how much was freed.
Menu bar

Runs quietly from the menu bar

Close the window and the app stays in the menu bar. For each watched folder it shows the free space on the volume that folder actually lives on, and how many worktrees are ready to remove.

  • Refreshes every 15 minutes, on Refresh now, and after every scan or cleanup.
  • When the window's list no longer matches the menu bar's count, the window says so and offers a rescan.
  • The background refresh never touches the network and never crawls node_modules.
  • On macOS you can hide the Dock icon.
  • Settings show how long the last refresh took and how many Git processes it started.

How it works

From picking a folder to free space in four steps.

  1. Pick a folder

    Click Choose Folder… and pick the directory that holds your projects.

  2. Let it scan

    A single scan finds node_modules folders, build folders and merged worktrees. Cards fill in as each scan returns, and Stop ends it.

  3. Review the results

    The overview shows the total, suggestions and each category's largest items; Review all › shows the full list. Tick whatever you don't need.

  4. Remove the selection

    Click Review and Remove…, go over the collected selection and confirm. Every category, caches included, is cleaned in one go.

Developer caches need no folder: the app scans them at launch, and Rescan caches scans them again. Go through the groups and check how each entry will be cleaned: deleted, emptied in place, or handed to the owning tool's prune command. Selected caches go to the same Review and Remove….

Download or build from source

Ready-made installers are on GitHub Releases. You can also build the app yourself.

Installers

  • Windows.msi · x64
  • macOS.dmg · Apple Silicon and Intel
  • Linux.deb, .AppImage · x64

Go to the latest release

The app isn't code-signed:

  • macOS: right-click → Open to get past Gatekeeper.
  • Windows: click “More info” → “Run anyway”.
  • Linux: the tray needs libayatana-appindicator3 (the .deb declares it). Without it the app still starts, just without the tray.

Build from source

You'll need Node.js 18+, the latest stable Rust, and the Tauri system prerequisites.

git clone https://github.com/jash90/developer-cleaner.git
cd developer-cleaner
npm install
npm run tauri dev     # development mode
npm run tauri build   # installers in src-tauri/target/release/bundle/

System dependencies:

  • Linux: sudo apt install libwebkit2gtk-4.1-dev libappindicator3-dev librsvg2-dev patchelf
  • macOS: xcode-select --install
  • Windows: Visual Studio C++ Build Tools
